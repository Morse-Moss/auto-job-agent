# Boss CDP 会话决策

## 问题

当前实现每轮启动新的 Chromium 上下文，并为每个岗位打开详情页。Boss 风控校验出现时，自动导航和重试会把一次校验放大成连续刷新。

## 选择

- 通过 Playwright `connect_over_cdp` 连接已有浏览器上下文，复用登录态。
- 登录态必须存在于配置的同一个 CDP profile（默认 `http://127.0.0.1:17332`）；应用内浏览器标签页是独立会话，不能互相替代。
- 一个批次只使用一个 Boss 页面；岗位详情通过列表卡片点击和 `detail.json` 响应读取，DOM 作为降级来源。
- 每次导航、点击和等待后检查安全校验 URL；命中后立即停止，不刷新、不重试、不发送。
- 以配置的较长随机间隔串行处理岗位，默认上限仍为 3 个。
- 对搜索 URL 按 `query`/`city` 语义比较，避免仅因参数顺序变化触发整页 `goto`。
- 长等待使用最多 500ms 的安全轮询；即使没有顶层 `framenavigated` 事件而出现 `_security_check`，也会在下一轮检查时停止。

## 明确不采用

- 新建浏览器上下文或每个岗位新开详情标签。
- 复制参考项目的反检测脚本。
- 自动重试导航、绕过滑块或处理验证码。

## 验收条件

- CDP 模式不调用 `new_context`，且一个批次不调用岗位级 `new_page`。
- 猎头、代招和明确外包岗位在 Provider 调用前被跳过。
- 安全校验 URL 出现时，GPT、发送和落库均不发生。
- 相同搜索页的 URL 参数顺序变化不触发新的文档导航；等待期间出现安全校验时在下一轮轮询停止。
- 聚焦测试和完整测试通过。
