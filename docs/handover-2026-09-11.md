## 五、整体架构与实现思路

分层保持 Python 模块化单体 + SQLite + 原生前端，个人本机运行，不引入微服务或前端框架。

```
用户更新岗位 → 采集与新鲜度 → 岗位理解与适配分析
用户确认 Word 基准 ─────────→ 岗位理解与适配分析
                              → 用户确认三套方向 → Word/PDF/长图资产
                              → 招呼语与简历选择
                              → 逐岗审阅并点击发送 → Boss 执行与证据核验
                              → 沟通进展 / 人工接管
```

四条贯穿性设计原则：

1. 职责隔离。所有外部动作经应用服务进入平台适配器；模型只产出建议与内容，不持有发送能力；渲染不访问 Boss，采集不调用模型或发送消息。
2. 浏览器单一租约。更新、旧采集、简历驱动采集、后续发送共用同一 `BrowserLease`。任一时刻只有一个持有者，冲突返回 409。
3. 持久化任务优于内存状态。长耗时操作返回任务标识，以数据库为真相源；重启把遗留 running 标记 interrupted，不自动联网恢复。
4. 逐岗授权。真实发送必须由用户逐岗点击，历史授权不能替代当前审核；页面加载与计划生成绝不触发外部动作。

采集侧关键机制：列表未见不等于岗位关闭（需连续两轮未见才升级，且仍非关闭证据）；失败保留旧 JD；登录失效、验证码、安全警告立即暂停且不重试不绕过。执行器的阶段状态机为 `queued → running → completed/partial/paused/failed/cancelled`，安全校验与登录失效暂停全部后续阶段。
